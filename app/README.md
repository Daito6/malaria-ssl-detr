# SmearScan

Веб-застосунок для демонстрації та використання моделей детекції й класифікації клітин на мікроскопічних
знімках мазків крові (BBBC041, P. vivax). Бекенд на FastAPI, фронтенд на React + TypeScript + Vite + Tailwind.

> **Дослідницький інструмент, не медичний виріб.** Результати не призначені для діагностики чи лікувальних
> рішень. Попередження показано в інтерфейсі постійно і додається до кожного експортованого PNG.

## Запуск

Потрібні conda-середовище `medthesis` (див. кореневий `README.md`), встановлений пакет проєкту (`pip install -e .`)
і Node.js 20+ (лише для збирання фронтенду).

```powershell
conda run -n medthesis pip install -r app/requirements.txt   # один раз
conda run -n medthesis python -m app                          # http://127.0.0.1:8000
```

`python -m app` збирає фронтенд, якщо `app/frontend/dist/` ще немає (`npm ci` + `npm run build`), і запускає сервер:
інтерфейс на `/`, документація API (OpenAPI) на `/docs`.

| Параметр | Що робить |
|---|---|
| `--device cpu` (за замовчуванням) | інференс на CPU; GPU приховано (`CUDA_VISIBLE_DEVICES=-1`) |
| `--device cuda` | інференс на GPU, лише коли його не займає тренування |
| `--rebuild` | перезібрати фронтенд |
| `--dev` | лише API; фронтенд окремо: `cd app/frontend; npm run dev` (http://127.0.0.1:5173, проксі `/api`) |
| `--host`, `--port` | адреса сервера (за замовчуванням `127.0.0.1:8000`) |

Ваги беруться тільки з локального кешу Hugging Face / timm (`HF_HUB_OFFLINE=1`), під час роботи нічого не
завантажується.

## Моделі (`app/models.yaml`)

| id | Тип | Файли |
|---|---|---|
| `a_coco_detr_binary` | end-to-end DETR (ResNet-50, COCO) | `runs/a_coco_detr_binary/{config.yaml, checkpoints/best.pt, thresholds.json}` |
| `b_vit_imagenet` | end-to-end ViT-DETR (ImageNet ViT-S/16, рецепт `full`) | `runs/b_vit_imagenet/...` |
| `b_vit_joint` | end-to-end ViT-DETR (SSL joint ViT-S/16) | `runs/b_vit_joint/...` + енкодер `runs/ssl_joint/checkpoints/encoder_final.pt` |
| `two_stage_dino` | двоетапна: рамки `a_coco_detr_binary` без класу + лінійний класифікатор на ознаках DINO ViT-S/16 | `runs/two_stage/ref_dino/train.pt` та ін. |

Новий end-to-end чекпойнт додається одним записом:

```yaml
  - {id: <run>, kind: detr, run: runs/<run>, name: {uk: "...", en: "..."}}
```

За замовчуванням чекпойнт — `runs/<run>/checkpoints/best.pt`, пороги — `runs/<run>/thresholds.json`. Якщо якогось
файлу немає, модель показано як недоступну з повним шляхом до відсутнього файлу. Для ViT-DETR, зібраного на
збереженому енкодері (`model.vit.init` — шлях у `config.yaml`), реєстр перевіряє і цей файл. Поле `normalization` при
завантаженні звіряється з моделлю: якщо не збігається, модель недоступна.

**Пороги за замовчуванням** читаються з файлів експериментів: для DETR це `thresholds.json` (обрано на val за
max F1), для двоетапної схеми — рядок `selection` у `reports/tables/phase5_two_stage_dino.json`. Для класу
uninfected двоетапної схеми поріг на val не обирався. Інтерфейс бере 0.5 і прямо пише біля повзунка, що це
типове значення інтерфейсу, а не результат відбору.

### Двоетапна модель: класифікатор відтворено перенавчанням

`scripts/two_stage.py evaluate` зберіг ознаки кропів, але не сам класифікатор. Тому застосунок один раз
перенавчає ту саму модель: обчислення `malaria_ssl.ssl.probe.linear_predict` (logreg зі збалансованими
класами, L2, L-BFGS, фіксовані гіперпараметри probe) на `runs/two_stage/ref_dino/train.pt`, варіант `clean`.
Параметри кешуються в `app/cache/two_stage_dino.pt` (git-ignored). Кеш записується лише після трьох перевірок,
результати яких лежать у `app/cache/two_stage_dino.json`:

1. параметри відтворюють сам `linear_predict` на збережених val-ознаках (`p_max_abs_diff`);
2. val infected AP50 і поріг max F1 на збережених val-кандидатах дорівнюють записаним в оцінці
   (`val_ap50` vs `val_ap50_reference`, `val_threshold` vs `val_threshold_reference`);
3. ознаки кропів, обчислені конвеєром застосунку з сирих val-знімків (CPU, fp32), збігаються зі збереженими
   (GPU, bf16): мінімальна косинусна подібність ≥ 0.99 на кандидатах перших трьох val-знімків.

Кеш перебудовується, якщо змінилися `train.pt`, варіант або гіперпараметри. **Еталонні метрики двоетапної
схеми лишаються в `reports/tables/phase5_two_stage_dino.csv`.** Застосунок нових метрик не обчислює і не
показує.

## Як рахується результат

- **Препроцесинг і нормалізація** такі самі, як у `scripts/evaluate.py`: застосунок імпортує з `malaria_ssl` ту
  саму функцію побудови моделі, eval-трансформацію (resize до довгої сторони 800), нормалізацію ImageNet, маску
  паддингу і декодування виходів. Від `scripts/` модуль `app/inference.py` не залежить. На CPU обчислення йде у
  fp32; `evaluate.py` працював у bf16 на CUDA.
- **NMS для показу.** Поверх виходу моделі бекенд виконує NMS без урахування класу з IoU 0.5. Для двоетапної
  схеми це той самий NMS, що в оцінці. Повзунок порогу на клієнті лише прибирає рамки з результату NMS, тому
  жодна клітина не з'являється двічі за будь-якого порогу. Протокол оцінки (`evaluate.py`) NMS не застосовує,
  тож кількості в застосунку не є метриками з `reports/`.
- **Клас і впевненість.** DETR: клас = argmax за справжніми класами, впевненість = його ймовірність (як в оцінці).
  Двоетапна: infected = objectness × p(infected), uninfected = objectness × (1 − p), клас = більше з двох.
- **Паразитемія** = infected / (infected + uninfected) серед рамок вище порогів. uninfected включає еритроцити і
  лейкоцити (бінарна схема з `configs/data.yaml`), клас `difficult` у навчанні не використовувався. Це не
  клінічний показник.

## Безпека й приватність

- Знімок надсилається сирим тілом запиту (`POST /api/jobs?model_id=...`, `Content-Type: image/jpeg|png`) і
  живе лише в пам'яті. На диск він не пишеться, у лог не потрапляє, після обробки видаляється. У лог іде метод,
  шлях, статус, тривалість, розмір у байтах і модель. Ім'я файлу на сервер не передається.
- Ліміти: 25 МБ на файл і 50 Мпікс. Кількість пікселів перевіряється за заголовком ще до декодування (захист від
  decompression bomb). Формат визначається за сигнатурою (JPEG/PNG), а не за розширенням.
- Інференс виконується в окремому потоці по одній задачі. Клієнт отримує id задачі й опитує прогрес
  (`GET /api/jobs/{id}`), тому інтерфейс не блокується.

## Аналіз (етап 1)

- Завантаження перетягуванням або вибором файлу; перегляд із зумом (колесо, кнопки, `+`/`-`/`0`) і панорамуванням
  (перетягування, стрілки).
- Вибір моделі, окремий повзунок порогу для кожного класу (перерахунок миттєвий), фільтр класів.
- Рамки розрізняються не лише кольором: uninfected має тонку пунктирну рамку з міткою «U», infected — товсту
  суцільну з «I». Кольори взято зі слотів 1–2 перевіреної категоріальної палітри (безпечні для дальтоніків),
  у світлій і темній темах свої відтінки.
- Підсумок: кількості, паразитемія з підказкою, розподіл впевненості для кожного класу з лінією порогу.
- Таблиця клітин із сортуванням. Клік по рядку підсвічує клітину й центрує на ній знімок; клік по рамці виділяє
  рядок.
- Експорт CSV (видимі клітини, піксельні координати оригіналу) та анотованого PNG у повній роздільності
  (з моделлю, sha256 і епохою чекпойнта, порогами, датою, застереженням).
- Українська та англійська мови, світла / темна / системна тема, адаптивна верстка.

## Порівняння (етап 2)

- Дві моделі поруч на одному завантаженому знімку, синхронний зум і панорамування (спільний стан переглядачів).
- Кожна модель зі своїми порогами (спільні з вкладкою «Аналіз»). Рамки зіставляються без урахування класу:
  жадібно за впевненістю, IoU ≥ 0.5 (`frontend/src/lib/match.ts`).
- Розбіжності трьох видів: «лише в A», «лише в B», «різний клас». На знімку вони позначені подвійною білою
  пунктирною рамкою і знаком «≠» у мітці, тобто не лише кольором.
- Під знімками різниця B − A для кількостей і паразитемії (у відсоткових пунктах) та список розбіжностей.
  Клік по рядку центрує обидва знімки на клітині.

## Робастність (етап 2)

**Жива демонстрація.**
- Знімок обирається лише з val (`GET /api/val-images`); test-знімки API не віддає.
- Режим «Одне спотворення»: тип і повзунок сили 0–1 з кроком 0.05. Режим «Стек» описано нижче. Запит іде через
  400 мс після останньої зміни (debounce).
- Зверху — вхід моделі (`GET /api/robustness/preview`), ширина пропорційна довгій стороні входу.
- Під ним три колонки (усі end-to-end DETR з реєстру: A, ViT-DETR ImageNet, joint) із синхронним зумом. У
  кожній колонці кількості infected / uninfected і паразитемія; різниця до сили 0 підсвічена значком ▲/▼ і фоном.
- Інференс іде через ту саму чергу задач. Результати кешуються за ключем (модель, знімок, канонічний стек):
  LRU на 512 записів на сервері плюс кеш у клієнті. Одне спотворення — це стек з одного кроку.

**Стек спотворень** (демонстрація, не протокол; крива рахується лише для одиночних спотворень).
- П'ять кроків: масштаб (↓ ×0.8 або ↑ ×1.27), фарбування, розмиття, яскравість/контраст, JPEG. У кожного свій
  вмикач і повзунок сили. Порядок застосування — згори донизу, номер у рядку; змінюється перетягуванням рядка
  або кнопками ↑ / ↓ (з клавіатури теж).
- Порядок за замовчуванням: масштаб → фарбування → розмиття → яскравість/контраст → JPEG (стиснення останнім).
- Вимкнені кроки і кроки з силою 0 відкидаються (`corruptions.canonical`), тож порожній стек — це оригінал і той
  самий ключ кешу. Масштаб першим = інший eval-ресайз, як в одиночному режимі; масштаб далі в стеку
  перемасштабовує вже спотворений вхід (`LongestMaxSize`, як eval-ресайз).
- Пресети: чотири вбудовані («Старий мікроскоп», «Стиснутий скан», «Інший барвник», «Розфокус»; сили
  ілюстративні, не з даних), власні зберігаються в localStorage цього браузера; експорт та імпорт JSON
  (`{"format": "smearscan-presets", "version": 1, ...}`, файл до 256 КБ, перевірка схеми).
- API: `POST /api/robustness/jobs` з `stack: [{kind, strength}, ...]`; `GET /api/robustness/{preview,describe}`
  з `stack=kind:s,kind:s`.

**Шторка «до/після».** Вигляд «Шторка» замість трьох колонок, одна модель на вибір.
- Ліворуч вхід без спотворення з детекціями цієї моделі, праворуч спотворений вхід з її ж детекціями; обидві
  половини в координатах оригіналу (знімок зі зміненим масштабом розтягнуто).
- Лінію поділу тягнуть мишею на знімку або повзунком під ним (стрілки, Shift — більший крок, Home / End). Під
  повзунком кількість рамок у кожній половині.
- Анімація сили: кадри 0, 0.1 … 1 (у стеку — множник для всіх сил). Спершу 11 кадрів обчислюються для вибраної
  моделі (індикатор «Готуємо кадри»), потім анімація лише програє кеш: play/pause, швидкість 0.5× / 1× / 2×,
  ручний вибір кадру. Сама анімація ніколи не стартує; при «менше руху» в системі про це є підпис.

**Спотворення** (`app/corruptions.py`) застосовуються **на вході моделі**, після eval-ресайзу, як зсув у
`evaluate.py --stain-shift`. Масштаб змінює довгу сторону входу, бо ресайз усього знімка фіксований eval-ресайз
скасував би. Сила 0 повертає оригінал.

| Тип | s → параметри | s = 1 |
|---|---|---|
| `stain` | HEDJitter 0.08·s + ColorJitter 0.3·s / 0.3·s / 0.3·s / відтінок 0.05·s; seed (2024, id знімка) | кольорова частина stain-shift probe |
| `blur` | гаусове, σ = 2·s px | σ = 2 px |
| `jpeg` | якість round(95 − 85·s) | 10 |
| `brightness_contrast` | контраст ×(1 − 0.5·s), яскравість ×(1 − 0.3·s) (лише затемнення) | ×0.5 / ×0.7 |
| `scale_down` | довга сторона 800·0.8^s | 640 (точка `--long-side 640` фази 4) |
| `scale_up` | довга сторона 800·1.27^s | 1016 (1.27 = відношення розмірів клітин у сирих test- і val-знімках; на вході моделі реальна різниця ×1.05, тож це верхня межа) |
| `stain_full` (лише в кривій, s = 1) | повний stain-shift probe | те саме, що `evaluate.py --stain-shift` |

Біля повзунка в UI пояснено, звідки беруться 1.27 і 640.

**Крива** (`scripts/robustness_curve.py`, протокол у `reports/robustness_plan.md`, EXPLORATORY, 1 seed, лише val).
- Вкладка «Крива» читає `reports/tables/robustness_val.csv` і `.json` через `GET /api/robustness/curve` і нічого
  не вшиває. Поки файлу немає, вона показує команди запуску.
- Графіки: infected AP50 і recall від сили, по лінії на модель зі смугою 95% CI. Є прямі підписи, підказка при
  наведенні (і з клавіатури, стрілками) і табличний вигляд.

## Тести й якість

```powershell
$env:CUDA_VISIBLE_DEVICES='-1'; conda run -n medthesis python -m pytest app/tests -q   # бекенд, лише CPU
conda run -n medthesis python -m ruff check --config app/ruff.toml app scripts/robustness_curve.py
conda run -n medthesis python -m ruff format --config app/ruff.toml --check app scripts/robustness_curve.py
cd app/frontend; npm test; npm run lint; npm run format:check; npm run build
```

- `test_inference_parity.py` запускається щоразу. Він порівнює застосунок із конвеєром `evaluate.py` на
  одному val-знімку запит за запитом (ті самі ваги й пристрій) і з `predictions_val.json` на рівні множини
  впевнених рамок. Також перевіряє кеш і ознаки двоетапної схеми. Якщо зміни в `malaria_ssl` (наприклад,
  `detr/build.py`) розійдуться із застосунком, тут з'явиться падіння.
- `test_nms.py`: після NMS немає пар з IoU > 0.5; підвищення порогу лише прибирає рамки.
- `test_api.py`: контракт OpenAPI, схеми відповідей, повний цикл задачі, великий знімок (6000×4500),
  відсутній чекпойнт (503 зі шляхом), некоректні файли, ліміт розміру.
- `test_corruptions.py`: сила 0 = оригінал, детермінованість, діапазон і формат, монотонність, відображення
  параметрів; `stain_full` побітово дорівнює stain-shift з `evaluate.py`.
- `test_robustness_api.py`: сила 0 = звичайний інференс для кожного типу; відтворюваність; рамки в пікселях
  оригіналу при масштабі; лише val; smoke усіх ендпоінтів і кешу; відсутній чекпойнт joint дає 503 зі шляхом.
- `test_corruption_stack.py`: порожній і нульовий стек = оригінал, нульові кроки відкидаються, стек з одного
  кроку = одиночне спотворення (для всіх типів), детермінованість, порядок має значення (blur→jpeg ≠ jpeg→blur),
  позиція масштабу, некоректні стеки. У `test_robustness_api.py` ще паритет інференсу (стек з одного = одиночне,
  нульовий стек = звичайний інференс) і API стеку з кешем.
- `test_robustness_curve.py`: сітка скрипта відповідає плану (26 умов на модель), кеш прогнозів читається без
  втрат. Крива при цьому не запускається.
- `test_uploads.py`, `test_registry.py`; фронтенд: `match.test.ts` (зіставлення і розбіжності), `filter.test.ts` (пороги без дублів, підсумок),
  `export.test.ts` (CSV з екрануванням, захист від формул), `stack.test.ts` (канонічний стек, порядок, пресети:
  round-trip, відмова на чужих файлах), `curtain.test.ts` (кадри туди-назад, швидкість, шторка під зумом і з
  клавіатури, половини).
