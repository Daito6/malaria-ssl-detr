# Адаптація без міток на BBBC041 test: підсумок (EXPLORATORY)

> **EXPLORATORY.** Гіпотезу сформульовано після того, як були відомі результати на BBBC041 test і NIH. Гіперпараметри
> зафіксовано на stain-shifted BBBC041 val до запуску на цілях (`reports/adapt_selection_frozen.md`); `config_sha256` у
> `reports/tables/adapt_bbbc_test_meta.json` збігається із зафіксованим (`9eec4bb4…`). На test нічого не обиралося, і
> найкращі рядки таблиць нижче не є вибором методу. Поправки на множинні порівняння немає (15 пар × 6 енкодерів × кілька
> метрик), тому окремі ДІ без 0 читаються обережно.

**Статус другої цілі.** Оцінка на NIH **не завершена**: запуск `adapt.py evaluate --target nih` (2026-11-01) обірвався
без запису `QUEUE DONE / FAIL` після 30 із 324 комбінацій (18 методів × 18 пар енкодер × бокси), таблиці пишуться лише в
кінці, тому результатів NIH немає. Середній час комбінації в лозі 394 с, тобто повний запуск ≈ 35 год (оцінка в черзі
4–6 год була заниженою). Значення з лога обірваного запуску тут не використовуються.

## 1. Протокол

- Схема: бокси A (3 seed, NMS 0.5) + лінійний класифікатор на замороженому енкодері, навчений на чистих train GT-кропах;
  скор `det_x_p`. Мітки цілі читає лише підрахунок метрик.
- Ціль: BBBC041 test, 120 зображень. ДІ — 95 %, bootstrap по зображеннях, 1000 ресемплів, seed 42. Парні різниці — на
  спільних ресемплах. Основні числа — `a_3s` (середнє трьох seed боксів).
- Запуск: `configs/queues/adapt_eval.txt`, 71 хв на CPU (`runs/adapt_eval/queue.log`).
- Таблиці: `reports/tables/adapt_bbbc_test_runs.csv`, `_diff.csv`, `_info.csv`, `_meta.json`. ДІ для `none` можуть трохи
  відрізнятися від `phase7_*` (інші ресемпли); точкові значення збігаються.

| метод | що робить | дані цілі |
|---|---|---|
| `none` | поріг max F1 на чистому val | немає |
| `none_stainthr` (контроль) | поріг max F1 на stain-shifted val | немає |
| `adabn` | вирівнює середнє / std ознак | уся ціль |
| `coral` (lam 1.0) | вирівнює середнє / стиснуту коваріацію | уся ціль |
| `cbr` (hard, 1 ітерація) | class-balanced вирівнювання з псевдомітками | уся ціль |
| `irc` (shrink 64, без масштабу) | центрування за медіаною клітин одного зображення | зображення + пул цілі |
| `+em` / `+bbse` | оцінка частки infected на цілі, перезважування постеріора, поріг за квантилем | уся ціль |

`irc_patient` на BBBC041 не рахується: пацієнтів немає.

## 2. Що показав вибір на val

На stain-shifted val жоден метод не перевищив `none` за AP50 (різниця −0.005…−0.009), а приріст F1 пояснювався порогом
(`reports/adapt_selection_frozen.md`). Отже з val-даних не випливало, що адаптація ознак допоможе.

## 4. Висновок (EXPLORATORY)

- **Глобальне вирівнювання ознак шкодить ранжуванню.** Для всіх SSL v2 енкодерів `adabn`, `coral`, `cbr` знижують AP50
  (−0.04…−0.12, ДІ без 0); `adabn` і `cbr` при цьому піднімають recall ціною precision.
- **`irc` дає невеликий приріст AP50** для b1 і b2 (+0.017…+0.020), але не для всіх енкодерів: ref_dino і cont2 без змін.
  На val такого приросту не було, тому це спостереження, а не передбачений результат.
- **Основний практичний ефект дає зміна порога, а не ознак.** Оцінка частки infected на цілі (`bbse`) піднімає recall на
  0.17–0.22 при майже незмінному AP50 для b1 і b2; precision падає на 0.06–0.09. Це стосується проблеми низького recall при
  порозі з val, а не якості класифікатора.
- `+em` / `+bbse` і `irc` використовують дані цілі (усю ціль або пул), тобто це трансдуктивний сценарій: потрібна партія
  немічених знімків нового домену.

Обмеження: 120 зображень test, 2 SSL-seed на енкодер, test уже багаторазово переглядався у фазах 4–7, поправки на
множинність немає. Чи переноситься це на NIH, невідомо, поки там не завершено оцінку.
